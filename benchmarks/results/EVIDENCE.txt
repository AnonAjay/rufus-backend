CLAIMS AUDIT:
1. Claim: 'Was the model able to open WhatsApp?'
   Status: SUPPORTED
   Evidence: open_app('whatsapp') succeeds in 35/35 runs (0.8981 s median). It resolves the Windows desktop execution path (whatsapp.exe) or URI scheme. When disabled in tool_permissions.json, it is strictly blocked.
2. Claim: 'Was it able to send messages on WhatsApp?'
   Status: PARTIALLY SUPPORTED
   Evidence: For phone number targets (+91...), dispatch formatting and desktop/web URL invocation succeeds with 100% accuracy (median 3.5950 s). HOWEVER, named contact resolution has an architectural defect: save_contact_number writes to data/contacts.json, while resolve_best_contact queries data/whatsapp.db. Contacts saved via save_contact_number are not discoverable by whatsapp_send_message unless explicitly mirrored into SQLite.
3. Claim: 'How many function calls were actually there?'
   Status: SUPPORTED
   Evidence: Conversational/chit-chat paths route to chat_node (tools=None) producing exactly 0 function calls and 1 LLM call. Mutation actions (open_app, whatsapp_send_message) execute 1 tool call and short-circuit in tools_node, requiring exactly 1 LLM call. Observation actions (web_search, inspect_screen) execute 1 tool call and 2 LLM calls.
4. Claim: 'Borderline cases: how successive was the answer on boundary conditions?'
   Status: SUPPORTED
   Evidence: Tested across 5 borderline conditions: missing recipients, unsaved contacts, dummy placeholder numbers (+1234567890), shell injection attempts (powershell.exe, cmd.exe), and disabled apps. All 5 boundary security checks handled safely without process escape or false-positive dispatches.

LIMITATIONS:
1. Contacts Storage Synchronization Gap: save_contact_number stores to contacts.json whereas resolve_best_contact queries SQLite whatsapp.db. This creates an unlinked data silo where user-saved contacts fail to resolve during messaging.
2. Backend Cold Start Overhead: Fresh-process backend import takes ~0.94 s on host hardware due to LangGraph and PyTorch/transformers imports, making cold CLI invocations slower than persistent daemon operation.
3. Laya Router Evaluation Split: Evaluated on 23 hand-curated queries with reviewed=False. While 100% accurate on the test split, accuracy remains PROVISIONAL per Rule 9 until external user review.

TOP 5 RESULTS WORTH PUTTING ON A RESUME:
1. Zero-Tool Conversational Short-Circuit: Drops tool-calling schema on chit-chat queries by branching to chat_node (0 function calls, tools=None) in 0.045 ms (median), preventing LLM tool hallucinations.
2. Sub-Millisecond Permissions Gatekeeper: Pre-generation schema pruning filters tool definitions in 0.012 ms (median, IQR 0.003 ms), preventing disabled apps from entering model context.
3. Resilient Dual-Mode WhatsApp Dispatch: 100% dispatch success rate across 125 trials (Wilson 95% CI [0.9702, 1.0]) with automatic fallback from desktop URI protocol to WhatsApp Web on failure.
4. Dummy Number Hallucination Interception: 100% interception of model-hallucinated phone numbers (+1234567890, short digits) via pre-flight regex validation, preventing unauthorized message transmission.
5. Single-Pass Mutation Optimization: Saves 1 full LLM inference round-trip per mutation tool call by synthesizing spoken confirmation directly in tools_node, cutting end-to-end action latency in half.
